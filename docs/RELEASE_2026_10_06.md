## Root-cause correction

The prior explanation that Coordination visuals existed in current code and only an old `f1c3a05` image was live was not accurate.

Before this release:

- The live API/web image tag was `operational-fd3f2fa`, not `operational-f1c3a05`.
- The repository had `CoordinationVisualContext`, but no `ProductHarborVisual` implementation.
- The operational `Berth` record did not accept coordinates.
- Coordination had a schematic berth view, call-to-thread display, and deadline view, but not a recorded-coordinate map or explicit `CALL -> THREAD -> PARTY` responsibility graph.

This release implements and verifies those missing product behaviors rather than documenting them as if they already existed.

## Coordination visual contract

The operational Coordination workspace now provides:

1. `RECORDED COORDINATE MAP` when one or more berth records include validated latitude and longitude.
2. `SCHEMATIC BERTH LAYOUT - NOT GEOGRAPHIC` for berths without recorded coordinates. Mixed datasets keep geocoded berths on the coordinate map and place only non-geocoded berths in the schematic fallback.
3. Active vessels/calls attached to their berth context.
4. A `CALL -> THREAD -> PARTY` responsibility graph with named accountable parties.
5. Thread state paths for handoffs, commitments, and obligations.
6. Cross-highlighting between a selected coordination thread, its call/vessel, responsible party, and deadline.
7. A `DUE-WINDOW TIMELINE` with overdue coordination visibly marked.
8. Existing evidence/detail/action cards preserved below the visual layer.

Operational berth records now accept optional validated `latitude` and `longitude` fields. Latitude is constrained to -90..90 and longitude to -180..180.
